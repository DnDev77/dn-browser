**English Version**
This system implements a tablet-style NUI interface for FiveM that allows players to access an embedded web page through an iframe within the game. Its main objective is to preserve the navigation state of the web interface per player during a session, ensuring that when the tablet is closed and reopened, the previously accessed page is restored. The architecture follows a client–server–NUI model and integrates with vRP to reliably identify players and validate active sessions. On the server side, the system validates the player using their user_id and source, stores the current iframe URL along with a timestamp in memory, manages session tokens, and periodically cleans expired cached data. On the client side, it controls the tablet open and close logic, manages NUI focus and input blocking, requests the saved state from the server, and forwards state updates received from the NUI. The NUI, built with React and TypeScript, renders the tablet interface, loads the saved URL when opened, monitors iframe navigation changes, and sends debounced save requests back to the server while maintaining a temporary in-memory state during usage. The overall flow ensures that the tablet behaves similarly to minimizing and reopening a browser, maintaining continuity as long as the server or resource is not restarted and the cache has not expired. For security, all state ownership and URL validation are handled server-side, restricting client authority and allowing only valid HTTP or HTTPS addresses. The system uses in-memory caching with a default expiration of twenty-four hours and does not include database persistence by default, which means state is lost on restarts but remains consistent during normal gameplay sessions.


**Portuguese Version**
Este sistema implementa uma interface NUI em formato de tablet para FiveM que permite aos jogadores acessar uma página web incorporada por meio de um iframe dentro do jogo. Seu principal objetivo é preservar o estado de navegação da interface web por jogador durante a sessão, garantindo que, ao fechar e reabrir o tablet, a última página acessada seja restaurada. A arquitetura segue o modelo cliente–servidor–NUI e é integrada ao vRP para identificar corretamente os jogadores e validar sessões ativas. No lado do servidor, o sistema valida o jogador utilizando user_id e source, armazena em memória a URL atual do iframe juntamente com um timestamp, gerencia tokens de sessão e realiza periodicamente a limpeza de dados expirados. No lado do cliente, o sistema controla a lógica de abertura e fechamento do tablet, gerencia o foco da NUI e o bloqueio de controles, solicita o estado salvo ao servidor e encaminha atualizações de estado recebidas da NUI. A NUI, desenvolvida em React e TypeScript, é responsável por renderizar a interface do tablet, carregar a URL salva ao ser aberta, monitorar mudanças de navegação no iframe e enviar solicitações de salvamento de forma controlada ao servidor, mantendo um estado temporário em memória enquanto o tablet está em uso. O fluxo geral garante que o tablet se comporte de maneira semelhante a minimizar e reabrir um navegador, mantendo a continuidade desde que o servidor ou o recurso não sejam reiniciados e que o cache não tenha expirado. Em termos de segurança, toda a validação de propriedade do estado e das URLs é feita no servidor, limitando a autoridade do cliente e permitindo apenas endereços HTTP ou HTTPS válidos. O sistema utiliza cache em memória com tempo padrão de expiração de vinte e quatro horas e não inclui persistência em banco de dados por padrão, o que significa que os dados são perdidos em reinicializações, mas permanecem consistentes durante sessões normais de jogo.
